# 设计简报：Git 仓库迁移工具

## 一句话描述

一款面向个人开发者和开发团队的 Windows 可视化桌面工具，在本地完成跨 Git 平台的单仓库或批量仓库迁移，无需将用户代码或仓库数据保存到产品服务端。

## 目标用户

- 主要用户：需要更换代码托管平台的个人开发者、团队管理员和企业研发人员。
- 用户特点：可能需要一次迁移几十到数百个仓库，源平台可能是公有平台或企业自建平台，不希望逐个创建目标仓库，也不希望代码经过第三方服务器。

## 核心场景

1. 用户连接源平台和目标平台，工具自动发现用户拥有、管理或参与的仓库，并按权限标记可迁移范围。
2. 用户按账号、组织、可见性、更新时间等条件批量选择仓库，使用“全选后排除”快速确定迁移集合。
3. 工具执行迁移预检，自动创建不存在的目标仓库，按队列迁移代码和可选平台数据，并在完成后生成校验报告。

## 第一版功能范围

### 平台支持

- GitHub。
- GitLab，包括 GitLab Self-Managed。
- Gitee。
- Gitea 和 Forgejo。
- 支持 Git over SSH/HTTPS 的通用 Git 服务。
- 已知平台支持 API 自动发现仓库；未知或无 API 平台支持手动导入单个或批量仓库 URL。

### 仓库发现与选择

- 展示用户自己创建、拥有管理权限和仅参与的仓库。
- 根据源平台权限将仓库标记为“可完整迁移”“仅可迁移 Git 数据”“权限不足”。
- 支持按账号、组织、仓库名称、可见性、更新时间等条件筛选。
- 支持全选筛选结果后排除少数仓库。
- 支持保存源仓库到目标仓库的映射清单。

### 迁移内容

- 默认迁移完整 Git 提交历史、全部分支和 Tag。
- 支持 Git LFS 对象迁移。
- 保留并检查 Submodule 配置，但不隐式迁移无权限访问的子仓库。
- README、License 等仓库内文件随 Git 历史迁移。
- 默认迁移仓库简介、项目主页、Topics/Tags、默认分支等基础元数据。
- Issues、PR/MR、Wiki、Release 及附件作为独立可选模块。
- 可见性变更和覆盖操作属于高风险选项，默认关闭并要求单独确认。

### 目标仓库创建与冲突

- 目标仓库不存在时，通过目标平台 API 自动创建。
- 目标仓库为空时默认复用。
- 目标仓库非空时默认跳过，不直接覆盖。
- 名称冲突时支持按规则自动改名后创建。
- 提供继续同步和覆盖迁移能力，但覆盖功能默认关闭，执行前必须展示影响范围并二次确认。
- 覆盖前应提供恢复信息或备份方案，避免不可逆数据丢失。

### 批量执行

- 支持至少 100 个仓库的批量迁移任务。
- 使用任务队列控制并发，避免平台限流和本机资源耗尽。
- 支持暂停、继续、失败重试和断点续传。
- 单个仓库失败不阻断其他仓库。
- 支持只运行预检、不执行迁移。

### 安全与隐私

- 迁移操作在用户本机执行。
- 产品服务端不保存用户代码、提交历史或平台数据。
- 凭据保存在 Windows 安全凭据存储中，日志必须脱敏。
- 使用最小权限访问令牌，并明确展示每个平台所需权限。
- 临时文件在任务完成或取消后按策略清理。

## 明确不做

- 第一版不提供 macOS 和 Linux GUI。
- 第一版不承诺迁移任意自研平台的 Issues、PR 等专属数据；没有兼容 API 时仅迁移 Git 数据。
- 第一版不自动绕过仓库所有权或权限限制。
- 第一版不默认删除、清空或强制覆盖目标仓库。
- 第一版不提供云端托管迁移任务。

## 成功标准

- 可批量迁移至少 100 个仓库，无需用户提前逐个创建目标仓库。
- 目标仓库创建、分支、Tag、默认分支和基础元数据符合用户配置。
- 每个分支的最新提交哈希或等价 Git 对象校验通过。
- Git LFS 对象在启用时完成数量与可访问性校验。
- 可选平台数据迁移后提供数量和失败项对照。
- 任务结果明确分类为“完整成功”“Git 数据成功但平台数据部分失败”“可重试失败”“权限或冲突跳过”。
- 中断后可以继续任务，不重复破坏已成功迁移的仓库。

## 产品形态

- Windows 可视化桌面应用是第一版主产品。
- 底层迁移引擎与界面解耦，为后续 CLI、自动化和其他桌面平台复用。
- 主要界面包含平台连接、仓库发现、筛选选择、字段映射、预检、任务队列、进度日志和迁移报告。
